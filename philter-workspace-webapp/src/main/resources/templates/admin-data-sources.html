S3-Compatible

Add S3-compatible data source

Works with any S3-compatible storage — Amazon S3, MinIO, Cloudflare R2, Backblaze B2, and similar. Specify the bucket, the key (prefix) under which to look, and a filename glob filter (for example *.txt or **/*.pdf). Names must be unique.

Use read-only, narrowly-scoped credentials. Grant the configured access key only s3:GetObject (and s3:ListBucket scoped via a prefix condition) on the specific bucket and key prefix configured above — and nothing else. No write, delete, or bucket-administration permissions are required for ingestion. Scoping the IAM policy (or equivalent) to the exact prefix ensures a compromise of these credentials cannot reach objects outside the data you intend to ingest. See the recommended IAM policy & AWS docs →

Leave the Endpoint URL blank to use Amazon S3 with the AWS default endpoint; set it to point at MinIO (e.g. http://minio:9000), Cloudflare R2, Backblaze B2, or any other S3-compatible storage. Leave Access key and Secret key blank to use the application's ambient AWS credentials (environment / instance profile). When provided, both keys are encrypted at rest with the application's symmetric key.

Relational Database

Add relational database data source

Register a JDBC-accessible database that documents can be pulled from. Specify the JDBC URL and a SQL query whose first column returns the document text. Names must be unique. Username and password are encrypted at rest with the application's symmetric key.

Use read-only, narrowly-scoped credentials. Philter Workspace validates the SQL query against an allow-list (only SELECT / WITH … SELECT are accepted; mutating statements, INTO OUTFILE / DUMPFILE file-write primitives, and dangerous driver parameters are refused). These checks are defence in depth — the authoritative protection is the database account itself. Grant the configured user only SELECT on the specific tables you intend to ingest from, and nothing else. See the credential & SQL safeguard docs →

Column 1 holds the document text. An optional column named filename supplies the per-row filename. For incremental ingest, reference :lastKey in a WHERE predicate and name the watermark column below.

Result-column name whose value is read from each row and used as the watermark for the next run. Pair this with a :lastKey placeholder and an ORDER BY on the same column in the SQL above. Leave blank to do a full-scan ingest each time.

Leave Username and Password blank to use credentials embedded in the JDBC URL or the driver's ambient authentication.
