Full text search

Backend: Embedded, set by PHILTER_WORKSPACE_SEARCH_BACKEND. Choosing a backend

Indexes each document's text in Philter Workspace itself so reviewers can search documents by their text on the Search page, and powers Find similar documents on the review page. No other service is needed.

Turning this on copies each document's original, unredacted text into the index at /app/data/search-index. The index files are encrypted with Philter Workspace's key and stored on disk. A document is removed from the index when it is deleted or its original text is cleared.

Off by default. Turning it off stops new documents from being indexed and leaves the Search page empty, but does not remove documents already indexed: delete the index directory, with Philter Workspace stopped, to remove them.

Indexes each ingested document into OpenSearch so reviewers can search documents by their text. When enabled, Philter Workspace writes the document text to the configured index on every ingest and serves the Search page from that index. The same index also powers the Find similar documents button on the document review page, which surfaces other documents in the same batch with related text.

Turning this on copies each document's original, unredacted text into OpenSearch, outside Philter Workspace's encryption at rest. Secure the cluster accordingly. A document is removed from the index when it is deleted or its original text is cleared.

Off by default. Turning it off stops new documents from being indexed and leaves the Search page empty, but does not remove documents already indexed: delete the index in OpenSearch to remove them.

                    Upper bound (in megabytes) on a single document submitted via the web upload
                    form or the POST /api/v1/ingest endpoint. Larger uploads are
                    rejected before they reach the redactor.

Max concurrent data imports

                

                    Caps how many data-import jobs (OpenSearch, Elasticsearch, …) can run
                    at the same time across the whole deployment. Additional jobs queue
                    as PENDING and run when a slot frees up. Per-batch
                    serialisation is independent and always enforced.

Detection rules

                

                    Reviewers can ask Philter to never flag a refused value again, or to always flag a value they
                    added by hand. A confirmed rule goes on the never-redact or always-redact list of the Philter
                    user whose key Philter Workspace redacts batches with, and applies to every batch in every
                    group.
                    Detection Rules
                


                

                    
                    

                        
                        
                        
How many times a value must be refused in one batch's
                            documents, and accepted in none of them, before Philter Workspace proposes never flagging
                            it. 0 turns proposals off. Default is 5.
